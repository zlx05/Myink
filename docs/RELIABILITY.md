# 生成与人工评审修复验收（2026-09-08）

## 已修复

- 9 月 9 日右栏信息架构调整：选中章节只显示最新一次生成任务的一份“章节流转”，逐节点展示耗时、token、费用和实际路由；审核报告、设定确认改为两个独立折叠模块。审核只显示最新一轮，未通过时自动展开；设定候选和历史记录严格按当前章节过滤。
- 正常长章在审核阶段触发 `CONTEXT_BUDGET_EXCEEDED`：此前把 12k 召回预算当成完整请求预算，扣除工具后仅剩 9468。现拆分可选记忆 12k 与完整请求 64k，并按模型窗口减输出预留检查。正文、硬约束不截断。实际失败的 3524 字草稿已在本地通过抽取、审核、修订提示词回放。
- 9 月 9 日交互简化：候选只提供“接受”和“不接受，自动修改”。修改意见可选，拒绝后自动启动 revise → extract → validate → audit → route，无需再点“继续评审”。旧稿未处理候选作废，保留历史；修订稿仍未通过则继续待人工，通过后才落库。
- 页面移除“仅不入库”，旧版本的拒绝记录和 API 兼容语义保留，不追溯猜测作者原意。明确的同人物、同状态变更按语义字段去重；自由文本改写仍依赖审核判断。
- 启动修改前按候选所属章节核对最新任务，批次还检查实际待处理章节。意见已保存但启动失败时显示“重试修改”，刷新后仍可从评审记录找回；成功后立即收起旧稿候选。
- 没有拒绝意见但有 pending 候选时，不能静默接受剩余候选。接受最后一条设定后自动续跑任务；若续跑失败，只显示“重试完成确认”，不要求重复接受。
- rewrite 与 replan 独立计数；干净 pass 不因先前轮次耗尽而误停。重规划带回上轮原因。单章任务的 batch 重规划建议按本章重规划执行；整批重规划也有次数上限。
- pass 同时携带 major/critical findings 时不能自动放行。缺失审核决策不能默认通过。
- route 运行记录包含实际去向、审核建议、规则计数和循环次数。实时区域与历史节点卡展示决策。待人工不再显示成已完成；待人工章节不计为批次完成。
- 非修仙题材也运行确定性检查，不因缺少 realm_order 跳过死而复生等通用校验；审核输入现在包含硬约束及确定性校验报告。
- 所有 awaiting_review 都暂停批次，不能跳过本章继续写下一章。

## 边界

5 个旧的 xfail 对应尚未实现的专门 L1 规则：首次来访、已毁物品、承诺兑现、能力前置条件、势力归属；这些旧测试没有提供正文，不能据其宣称语义审核失败或规则已经实现。新增的真实模型正反例验证了审核路径，但不构成任意小说零漏检的保证。

本次没有把用户原小说发送给模型重跑。自动审批拒绝了该项私有数据外发回放；已完成原失败现场的本地请求回放，并使用纯合成内容完成真实模型测试。原失败任务保留，可由作者在更新后重试。

前端仍有既有的 hook/热更新 lint 警告和 bundle 大小提示；测试容器还有依赖弃用、pytest 配置及 demo JWT 长度警告。本次未改变这些与生成逻辑无关的配置。
